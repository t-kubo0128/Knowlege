コマンドって何？ パッケージマネージャ、PATH、インターネットからのインストールの仕組みを、日常の例えで理解する 1. コマンドとは何か 簡単に言えば、「コンピュータに仕事を頼むための指示文」です。 例え：レストランで注文する あなたが「カレーライスをください」と店員に言えば、厨房でカレーが作られて出てきます。 コンピュータの場合、あなたがターミナルに git --version と打てば、git というプログラムに「自分のバージョンを教えて」と頼んでいるのです。 つまり、コマンド = プログラムの名前 なのです。git も npm も brew も、最初からパソコンに入っている「プログラム」か、あなたが後から入れた「プログラム」かの違いしかありません。 2. なぜコマンドでインストールできるのか ここで「パッケージマネージャ（Package Manager）」という概念が登場します。 例え：スーパーマーケットで買い物する あなたが「牛乳をください」と店員に言えば、店の倉庫から牛乳を取り出して渡してくれます。 パッケージマネージャはまさにこの「店員」です。 → brew は「Homebrewという名前の店」の店員 → npm は「npmという名前の店（Node.js専門）」の店員 実際に何が起きているか 1 あなたが brew install git と入力する 2 brewプログラムが起動し、「gitを探せ」と判断する 3 brewがインターネット上の「Homebrewの倉庫（リポジトリ）」に接続する 4 倉庫から「gitのインストール手順書（Formula）」を取得する 5 手順書に従い、ソースコードをダウンロード・コンパイル・配置する 6 完了！これで git コマンドが使えるようになる 3. 「brewは最初から使える」のは誤解 よくある誤解 「npmやgitはインストールしないと使えないのに、なぜbrewは最初から使えるの？」 答え：brewも最初から使えません。 先ほどのガイドで、まず以下のコマンドを実行しましたよね。 /bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/.../install.sh)" これが「Homebrewのインストール」です。 つまり、brewもnpmもgitも最初は入っていません。すべて後からインストールする必要があります。ただ、brewのインストール方法が「1行のコマンド」なので、「最初からある」ように見えるだけなのです。 コマンド 最初から入っている？ どうやって入れる？ git × 入っていない brew install git npm × 入っていない Node.jsをインストールすると一緒に入る brew × 入っていない インストールスクリプトを実行 ls, cd ◯ macOSに最初から入っている 不要 4. インターネットのパッケージがダウンロードできる仕組み 4-1. 倉庫（リポジトリ）がある Homebrewには、インターネット上に「ソフトウェアのカタログとインストール手順」をまとめた巨大な倉庫があります。GitHub上で公開・管理されています。 例え：通販カタログ ベルメゾンのカタログのように、「どの商品がどこにあるか」「どうやって組み立てるか」が記載されています。brewはこのカタログを見て、必要なファイルを正しい場所からダウンロードします。 4-2. ダウンロードからインストールまで Step 1：カタログを確認 brewがGitHubの倉庫にアクセスし、「gitの最新版はどこにあるか」を確認します。 Step 2：ファイルをダウンロード 確認したURLから、gitのソースコード（またはコンパイル済みのバイナリ）をダウンロードします。これはブラウザでファイルをダウンロードするのと同じ仕組みです。 Step 3：パソコン内に配置 ダウンロードしたファイルを、macOSの決まった場所（通常は /opt/homebrew/ 以下）に展開・配置します。 Step 4：PATHを通す（重要） 配置した場所を、シェル（ターミナル）に「ここにもコマンドがあるよ」と教えます。これを「PATHを通す」と言います。 5. PATHって何？（最も重要な概念） ここが一番混乱しやすいポイントです。 例え：学校の「呼び出し番号リスト」 学校に「3年2組の田中はどこにいますか？」と聞かれたとき、先生は名簿を見て場所を教えます。 PATHはまさにこの「名簿」です。ターミナルが git と入力されたとき、「gitというプログラムはどのフォルダにいるか」を調べる名簿がPATHなのです。 # PATHの中身を見るコマンド echo $PATH # 出力例（フォルダのリストが : で区切られて表示される） # /usr/local/bin:/usr/bin:/bin:/opt/homebrew/bin つまり、brewがgitをンストールしたあとに git と打てば使えるのは、brewが「/opt/homebrew/bin」というPATHの名簿に載っている場所にgitを置いてくれたからです。 まとめ：コマンドが使えるようになる条件 • そのプログラムがパソコン内のどこかに存在している • その場所がPATHに登録されている この2つが揃えば、どのコマンドも使えるようになります。 6. 全体の図解 インターネット Homebrew倉庫（GitHub） 1. カタログを取得 brew（パッケージマネージャ） 「店員」役割 2. ファイルをダウンロード /opt/homebrew/bin/git インストール先（パソコン内） 3. PATH登録 PATH 「名簿」 /opt/homebrew/bin $ git --version ターミナル（あなた） 4. PATH名簿を見て発見！ Homebrewによるインストールの全体像 7. 確認してみよう あなたのMacで、以下のコマンドを順番に試してみてください。目で見て確認するのが一番です。 # 1. PATHの中身を見る echo $PATH # 2. gitがどこにあるか探す which git # 3. brewがどこにあるか探す which brew # 4. インストール済みパッケージ一覧を見る brew list which git で /opt/homebrew/bin/git のようなパスが表示されれば、gitがその場所にあり、PATHにも登録されている証拠です。 コマンドは「パソコンへの指示文」、パッケージマネージャは「ソフトウェアの店員」、PATHは「場所の名簿」 この3つを覚えれば、インストールの仕組みが見えてきます
